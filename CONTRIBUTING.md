# Contributing

Thanks for pitching in. Before you open a PR, skim the conventions below so your changes land without a review cycle of style nits.

## Project structure

```
src/
├── client/
│   └── index.ts         # RevenueCat class, httpHandler, type exports
├── component/           # Convex component (backend)
│   ├── _generated/      # Auto-generated by `npm run build:codegen`. Do not edit.
│   ├── convex.config.ts # Component registration
│   ├── schema.ts        # Tables + validators
│   ├── handlers.ts      # Webhook event handlers (17 canonical + 2 legacy)
│   ├── webhooks.ts      # Dedup, rate limit, dispatch
│   ├── transitions.ts   # Lifecycle hook snapshot/diff/fire
│   ├── lib.ts           # Shared helpers
│   ├── customers.ts     # Queries + purge mutation
│   ├── subscriptions.ts # Queries
│   ├── entitlements.ts  # Queries + grant/revoke internal mutations
│   ├── experiments.ts   # Queries + upsert
│   ├── transfers.ts
│   ├── invoices.ts
│   ├── virtualCurrency.ts
│   ├── sync.ts          # REST reconciliation from `/v1/subscribers/{id}`
│   ├── webhookEvents.ts # Audit log
│   ├── cleanup.ts       # Paginated `webhookEvents` retention cleanup
│   ├── crons.ts         # Scheduled jobs
│   └── types.ts         # Public type exports
└── test.ts              # `revenuecatTest.register(t)` helper for consumers
example/
└── convex/              # Consumer-style integration target
```

Tests sit next to the module they cover (`handlers.test.ts` next to `handlers.ts`, etc.). New handlers ship with new tests in the same commit.

## Development

```bash
npm install
npm run dev       # Convex dev server + codegen watch
npm run all       # Dev server + test watch
```

## Testing

```bash
npm run test              # Full suite
npm run test -- --watch   # Watch mode
npm run test -- handlers  # One file
npm run typecheck         # tsc --noEmit + example typecheck
npm run lint              # ESLint
npm run validate          # test + lint + typecheck in one shot
```

`npm run validate` is what `prepack` and `prepublishOnly` run. Keep it green.

## Building

```bash
npm run build         # Compile to `dist/`
npm run build:codegen # Regenerate `_generated/` then compile
npm run build:clean   # Clean + rebuild
```

## Pull requests

1. Fork and branch from `main`.
2. Write the code AND the tests in the same commit.
3. Run `npm run validate`.
4. Follow conventional commits for each commit: `type(scope): lowercase description` under 72 chars, no trailing period. Preferred verbs: add, fix, extract, drop, rename, move, split, wire, swap.
5. Update `CHANGELOG.md` under `## [Unreleased]` for any user-visible behavior change or API addition. Reference file paths and symbols with backticks.
6. For webhook-semantic changes, cross-reference against [RC's event types doc](https://www.revenuecat.com/docs/integrations/webhooks/event-types-and-fields). Speculative handling of undocumented wire values has a bad track record in this codebase (see the `cancel_reason: "SUBSCRIPTION_PAUSED"` removal in 0.2.0).
7. Open the PR with a first line stating what changed and why. No preamble, no headers, no bold-prefixed bullets.

## Code style

- TypeScript `strict: true`. No implicit `any`.
- Convex functions require `args` and `returns` validators.
- **Webhook handler args use `v.any()`**, not `v.object`. RC reserves the right to add fields without versioning, and a strict validator drops real events. The `EventPayload` type exists as documentation; cast inside the handler.
- **Query return validators use the schema pattern**: `schema.tables.X.validator.extend({ _id: v.id("X"), _creationTime: v.number() })`. No re-declaring field lists.
- **`hasEntitlement` and `getActive` stay pure-expiry**: `isActive && (expiresAtMs === undefined || expiresAtMs > now)`. Grace periods are folded into `expiresAtMs` by `processBillingIssue` and `syncSubscriber`. Do not add short-circuits on `billingIssueDetectedAt` or other auxiliary flags. This mirrors the iOS SDK's `EntitlementInfo.isActive` and is the reason access stops cleanly at grace end even if `EXPIRATION` is dropped.
- Every new handler starts with `await recordEvent(ctx, event)` (upserts the customer, hydrates experiments). Don't call `upsertCustomer` directly.
- New state transitions flow through `snapshotEntitlements` + `fireTransitionHooks` so lifecycle hooks fire atomically with the mutation.
- Use `internalMutation` for component writes. `mutation` and `query` are public surface.
- Small functions. One concern per function. Early returns. No deep nesting.
- No TODOs without a linked issue.
- No dead code. If it's unused, delete it.

## Release

Releases are cut from `main`. The flow:

```bash
npm run release   # patch bump (0.y.z -> 0.y.z+1)
npm run alpha     # prerelease (adds `-alpha.N`)
```

Version rules for pre-1.0:

- **PATCH** (`0.2.0 → 0.2.1`) is for backward-compatible bug fixes only. No observable behavior changes, no new API, no changed return shapes.
- **MINOR** (`0.2.x → 0.3.0`) for anything that changes observable behavior, adds public API, tightens types, or adds required fields to existing return shapes. In pre-1.0 this also stands in for breaking changes (see `0.1.x → 0.2.0` as the template).
- **MAJOR** (`1.0.0`) once the API surface is stable enough to commit to.

Tag-driven GitHub Action handles the npm publish. Before tagging:

1. Confirm `CHANGELOG.md` has a dated heading for the version.
2. Run `npm run validate`.
3. Run `npm audit --audit-level=high` (should be clean).

## Security

Report vulnerabilities by email rather than public issues. A written `SECURITY.md` is coming; in the meantime, reach the maintainer through the contact on their GitHub profile.
